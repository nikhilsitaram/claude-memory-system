# E5: Remove dead code from markdown-era pipeline

**Avoid:** Do not remove functions that are still needed for v2-to-v3 migration (`_parse_ltm_entries`, `_parse_daily_entries` in storage.py) -- add a deprecation comment but keep them. Do not remove `get_daily_dir`, `get_global_memory_file`, or `get_project_memory_dir` from memory_utils.py if they're still referenced by the migration code in storage.py -- check all callers first. Do not remove all tests at once -- remove tests for each deleted function individually, running the suite after each batch to catch cascading failures.

## Steps

### Step 1: Audit callers of each dead function

Before removing anything, grep for each function name across the codebase. Build a removal list grouped by file. Only remove functions with zero live callers (migration-only callers are acceptable to keep).

### Step 2: Remove dead functions from load_memory.py

- `load_project_memory()` -- replaced by SQL query

- `load_project_history()` -- replaced by SQL query

- `_build_synthesis_instructions()` -- replaced by `_build_synthesis_instructions_v3`
- `_build_preextracted_prompt()` -- keep a slimmed version for v3, or replace entirely

Update tests: remove test classes/methods that test deleted functions.

- `build_dailies_from_project_blocks()` -- no daily files
