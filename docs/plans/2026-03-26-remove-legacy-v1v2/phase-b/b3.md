# B3: Remove LTM references from project_manager.py list/plan operations

**Avoid:** Do not remove LTM references from `restore_from_backup()` or `get_memory_files_for_merge()` -- users may still have legacy markdown files that need to be restorable. Only clean the list/plan/merge_orphan operations that actively reference `*-long-term-memory.md` as a data source. Be surgical: `project_manager.py` is 1537 lines and most of it is v3 code.

## Steps

### Step 1: Identify LTM references

Search for `long-term-memory` in project_manager.py:
```bash
grep -n "long-term-memory" scripts/project_manager.py
```

The design doc says to remove references from `list_projects()`, `plan_move()`, and `plan_merge_orphan()`. Keep references in `restore_from_backup()` and `get_memory_files_for_merge()`.

### Step 2: Clean list_projects()

Find `list_projects()` and remove any code that scans for or displays `*-long-term-memory.md` files. This likely includes lines that glob project LTM files and include them in the listing output.

### Step 3: Clean plan_move()

Find `plan_move()` and remove any code that includes `*-long-term-memory.md` files in the move plan. The move plan should only reference DB data_points, not markdown files.

### Step 4: Clean plan_merge_orphan()

Find `plan_merge_orphan()` and remove any code that includes `*-long-term-memory.md` files in the merge plan.

### Step 5: Update test_project_manager.py

Find and update tests that assert LTM files are included in list/plan/merge output. Remove assertions about `*-long-term-memory.md` from these test classes.

Keep tests for `restore_from_backup()` and `get_memory_files_for_merge()` that reference LTM files -- these are intentionally preserved.

### Step 6: Run tests

```bash
python3 -m pytest tests/test_project_manager.py -q
```
