# A1: Fix false health alert for v3 DBs with legacy tables

**Avoid:** Do not remove the `chunks`/`nodes` query branches entirely -- they must remain for any DB still at user_version < 3 (e.g., test DBs created with `_make_v2_db`). The fix is about *priority order*, not deletion. Check `user_version` first and skip legacy branches when >= 3.

**Avoid:** Do not change `format_report` or `HealthReport` dataclass -- only `health_report()` and `health_alerts()` logic is affected.

## Steps

### Step 1: Write failing tests in tests/test_health.py

Add a new test class `TestHealthV3LegacyTableBug` with two tests:

1. `test_v3_db_with_empty_chunks_table_not_empty_alert` -- Creates a v3 DB, manually creates an empty `chunks` table (`CREATE TABLE chunks (id TEXT, salience REAL, source_type TEXT)`), inserts 5 `data_points` memories, then asserts `health_report(conn).total_chunks == 5` and `health_alerts(report)` does NOT contain "empty".

2. `test_v3_db_with_legacy_nodes_table_uses_data_points` -- Creates a v3 DB, manually creates a `nodes` table with 0 rows (`CREATE TABLE nodes (id TEXT, name TEXT)`), inserts 2 entity `data_points`, then asserts `health_report(conn).graph_nodes == 2`.

Use the existing `_make_db(tmp_path)` helper to create the v3 DB. After creating the DB, manually execute `CREATE TABLE IF NOT EXISTS chunks (...)` and `CREATE TABLE IF NOT EXISTS nodes (...)` to simulate the legacy state.

Run: `python3 -m pytest tests/test_health.py::TestHealthV3LegacyTableBug -v` -- expect 2 failures.

### Step 2: Fix health_report() in scripts/health.py

In `health_report()`, around line 87, the current logic is:

```python
if 'chunks' in tables:
    # v2 schema: query chunks table
    ...
elif 'data_points' in tables:
    # v3+ schema
    ...
```

The bug: `chunks` table exists (0 rows from migration) so the `if` branch fires, returning `total_chunks=0`, which triggers the "DB empty" alert.

Fix: Check `report.schema_version` first. When `>= 3`, go directly to the `data_points` branch regardless of whether `chunks` exists:

```python
if report.schema_version >= 3 and 'data_points' in tables:
    # v3+ schema: query data_points table with type filter
    row = conn.execute("""
        SELECT
            COUNT(*) as total,
            ...
        FROM data_points WHERE type = 'memory'
    """).fetchone()
elif 'chunks' in tables:
    # v2 schema: query chunks table
    row = conn.execute("""
        ...
        FROM chunks
    """).fetchone()
elif 'data_points' in tables:
    # Fallback for v3 without version pragma (shouldn't happen)
    row = conn.execute("""
        ...
        FROM data_points WHERE type = 'memory'
    """).fetchone()
else:
    row = (0, 0, 0, 0, 0, 0, 0)
```

Apply the same pattern for the graph statistics block (lines 126-136):

```python
if report.schema_version >= 3 and 'data_points' in tables:
    report.graph_nodes = (
        conn.execute(
            "SELECT COUNT(*) FROM data_points WHERE type = 'entity'"
        ).fetchone()[0] or 0
    )
elif 'nodes' in tables:
    report.graph_nodes = (
        conn.execute("SELECT COUNT(*) FROM nodes").fetchone()[0] or 0
    )
elif 'data_points' in tables:
    report.graph_nodes = (
        conn.execute(
            "SELECT COUNT(*) FROM data_points WHERE type = 'entity'"
        ).fetchone()[0] or 0
    )
```

### Step 3: Run tests and verify

Run: `python3 -m pytest tests/test_health.py -v` -- all tests pass including the 2 new ones.
