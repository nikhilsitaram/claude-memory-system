# A5: Passive vs active reinforcement in load_memory

**Avoid:** Do not change the REINFORCEMENT_ETA constant (0.18) or the decay formula. The fix is about *when* reinforcement is applied, not *how much*.

**Avoid:** Do not change MCP search or other active access paths -- they should continue to use the default `passive=False` which applies full reinforcement. Only the `_load_from_db` SessionStart auto-loading call changes to `passive=True`.

**Avoid:** Do not remove `access_count` or `last_accessed` tracking from passive loads -- these are still useful for analytics. Only salience reinforcement and neighbor boosting are skipped.

### Step 2: Add passive parameter to _batch_update_data_point_access

In `scripts/load_memory.py`, modify `_batch_update_data_point_access` (starts at line 479):

```python
def _batch_update_data_point_access(
    conn: sqlite3.Connection, dp_ids: list[str], passive: bool = False
) -> None:
    """Increment access_count, update last_accessed, and optionally reinforce salience.

    Args:
        conn: Database connection.
        dp_ids: List of data_point IDs to update.
        passive: If True, skip salience reinforcement and neighbor boosting.
            Used for SessionStart auto-loading which is not a usefulness signal.
            access_count and last_accessed are still updated for analytics.
    """
    if not dp_ids:
        return
    timestamp = datetime.now(timezone.utc).isoformat().replace("+00:00", "Z")
    placeholders = ",".join("?" for _ in dp_ids)
    conn.execute(
        f"UPDATE data_points SET access_count = access_count + 1, "
        f"last_accessed = ? WHERE id IN ({placeholders})",
        [timestamp] + list(dp_ids),
    )

    # Skip salience reinforcement and neighbor boosting for passive loads
    if passive:
        return

    # Batch-fetch saliences to avoid N+1 queries
    salience_rows = conn.execute(
        f"SELECT id, salience FROM data_points WHERE id IN ({placeholders})",
        list(dp_ids),
    ).fetchall()
    salience_map = {row[0]: row[1] for row in salience_rows}

    for dp_id in dp_ids:
        if dp_id not in salience_map:
            continue
        current = salience_map[dp_id] if salience_map[dp_id] is not None else 1.0
        new_sal = min(1.0, current + REINFORCEMENT_ETA * (1.0 - current))
        conn.execute(
            "UPDATE data_points SET salience = ? WHERE id = ?",
            (new_sal, dp_id)
        )

        neighbors = conn.execute(
            "SELECT DISTINCT e.target, dp2.salience, e.weight FROM edges e "
            "JOIN data_points dp2 ON dp2.id = e.target "
            "WHERE e.source = ? AND e.valid_to IS NULL "
            "AND dp2.type = 'entity'",
            (dp_id,)
        ).fetchall()
        for target_id, neighbor_sal, edge_weight in neighbors:
            boost = REINFORCEMENT_ETA * (edge_weight if edge_weight is not None else 1.0) * new_sal
            new_neighbor_sal = min(1.0, (neighbor_sal if neighbor_sal is not None else 0.5) + boost)
            conn.execute(
                "UPDATE data_points SET salience = ? WHERE id = ?",
                (new_neighbor_sal, target_id)
            )
```

### Step 3: Update _load_from_db to pass passive=True

In `_load_from_db` (around line 671), change the access tracking call:

```python
# Access tracking for all served data_points
if seen_ids:
    try:
        _batch_update_data_point_access(conn, list(seen_ids), passive=True)
        conn.commit()
    except Exception as e:
        print(f"Warning: Access tracking failed: {e}", file=sys.stderr)
```

This single change ensures that all SessionStart auto-loaded memories get `access_count` and `last_accessed` updates but NO salience reinforcement. The existing decay (HOT tier lambda=0.005) will naturally reduce salience over time for memories that are not actively accessed via MCP search or user prompt recall.
