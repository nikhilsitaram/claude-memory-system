# A9: Fix hamming distance signed integer bug

**Avoid:** Do not silently mask the signed integer by auto-casting (e.g., `a & 0xFFFFFFFFFFFFFFFF`) -- the design doc specifies raising a ValueError with an explicit message telling the caller how to cast. This is because silent auto-masking hides the upstream bug (SQLite returning signed integers). Do not change `compute_simhash` -- it already returns unsigned integers. The fix is solely in `hamming_distance`.

## Steps

### Step 1: Write failing tests for signed integer guard

In `tests/test_simhash.py`, add:

```python
class TestHammingDistanceSignedGuard:
    """Tests for hamming_distance rejection of signed (negative) integers."""

    def test_negative_a_raises_value_error(self):
        import pytest
        from simhash import hamming_distance
        with pytest.raises(ValueError, match="non-negative"):
            hamming_distance(-1, 42)

    def test_negative_b_raises_value_error(self):
        import pytest
        from simhash import hamming_distance
        with pytest.raises(ValueError, match="non-negative"):
            hamming_distance(42, -1)

    def test_both_negative_raises_value_error(self):
        import pytest
        from simhash import hamming_distance
        with pytest.raises(ValueError, match="non-negative"):
            hamming_distance(-100, -200)

    def test_error_message_includes_cast_hint(self):
        import pytest
        from simhash import hamming_distance
        with pytest.raises(ValueError, match="0xFFFFFFFFFFFFFFFF"):
            hamming_distance(-1, 0)

    def test_zero_values_still_work(self):
        from simhash import hamming_distance
        assert hamming_distance(0, 0) == 0

    def test_large_unsigned_values_still_work(self):
        from simhash import hamming_distance
        a = (1 << 63) + 42  # Large unsigned 64-bit value
        b = (1 << 63) + 43
        result = hamming_distance(a, b)
        assert isinstance(result, int)
        assert result >= 0

    def test_are_near_duplicates_also_guarded(self):
        """are_near_duplicates delegates to hamming_distance, so it inherits the guard."""
        import pytest
        from simhash import are_near_duplicates
        with pytest.raises(ValueError, match="non-negative"):
            are_near_duplicates(-1, 42)
```

Run tests, confirm they fail (current `hamming_distance` accepts negative values).

### Step 2: Add the guard to hamming_distance

In `scripts/simhash.py`, replace the `hamming_distance` function:

```python
def hamming_distance(a: int, b: int) -> int:
    """Compute the Hamming distance between two 64-bit SimHash fingerprints.

    Args:
        a: First fingerprint (must be non-negative).
        b: Second fingerprint (must be non-negative).

    Returns:
        Number of differing bit positions (0-64).

    Raises:
        ValueError: If either argument is negative. SQLite stores 64-bit integers
            as signed; cast with ``val & 0xFFFFFFFFFFFFFFFF`` before comparing.
    """
    if a < 0 or b < 0:
        raise ValueError(
            f"Both arguments must be non-negative unsigned 64-bit integers "
            f"(got a={a}, b={b}). Cast SQLite values with: val & 0xFFFFFFFFFFFFFFFF"
        )
    return bin(a ^ b).count("1")
```

```bash
python3 -m pytest tests/test_simhash.py -v

```

All tests pass, including existing tests for positive values.
