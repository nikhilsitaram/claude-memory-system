# B2: Switch session continuity and recent activity loading to working days

**Avoid:** Don't change the SQL queries' structure — only the date parameters change. Don't remove the fallback to calendar days — new projects or empty projects won't have working days, and the loader must still work. Don't import `get_global_working_days` / `get_project_working_days` at the top level of `load_memory.py` — it runs as a SessionStart hook and import cost matters. Import inside the function or use a lazy pattern.

### Step 2: Modify Tier 2 (session continuity) to use project working days

In `scripts/load_memory.py`, at the session continuity section (~line 769):

**Before:**
```python
if project_scope:
    seven_days_ago = (
        datetime.now(timezone.utc) - timedelta(days=7)
    ).isoformat().replace("+00:00", "Z")

    row = conn.execute(
        "SELECT id, content, properties FROM data_points "
        "WHERE type='session_context' AND scope=? AND created_at > ? "
        "ORDER BY created_at DESC LIMIT 1",
        (project_scope, seven_days_ago)
    ).fetchone()
```

**After:**
```python
if project_scope:
    from memory_utils import get_project_working_days

    working_days = get_project_working_days(project_scope, 5)
    if working_days:
        # Use oldest working day as cutoff
        cutoff = working_days[-1] + "T00:00:00Z"
    else:
        # Fallback: 7 calendar days
        cutoff = (
            datetime.now(timezone.utc) - timedelta(days=7)
        ).isoformat().replace("+00:00", "Z")

    row = conn.execute(
        "SELECT id, content, properties FROM data_points "
        "WHERE type='session_context' AND scope=? AND created_at > ? "
        "ORDER BY created_at DESC LIMIT 1",
        (project_scope, cutoff)
    ).fetchone()
```

The SQL query stays the same — only the `cutoff` parameter changes. By using the oldest date from `get_project_working_days(scope, 5)` as the lower bound, we capture any session_context from the last 5 project working days.

### Step 3: Modify Tier 5 (recent activity) to use global working days

In `scripts/load_memory.py`, at the recent activity section (~line 836):

**Before:**
```python
three_days_ago = (
    datetime.now(timezone.utc) - timedelta(days=3)
).isoformat().replace("+00:00", "Z")

scope_param = project_scope or "global"
rows = conn.execute(
    "SELECT id, content FROM data_points "
    "WHERE scope IN ('global', ?) AND type='memory' "
    "AND created_at > ? "
    "ORDER BY created_at DESC LIMIT 15",
    (scope_param, three_days_ago)

```

**After:**

```python
from memory_utils import get_global_working_days

global_working = get_global_working_days(3)
if global_working:
    cutoff = global_working[-1] + "T00:00:00Z"
else:
    cutoff = (
        datetime.now(timezone.utc) - timedelta(days=3)
    ).isoformat().replace("+00:00", "Z")

scope_param = project_scope or "global"
rows = conn.execute(
    "SELECT id, content FROM data_points "
    "WHERE scope IN ('global', ?) AND type='memory' "
    "AND created_at > ? "
    "ORDER BY created_at DESC LIMIT 15",
    (scope_param, cutoff)
).fetchall()
```

Same pattern: SQL query unchanged, only the cutoff parameter changes.
